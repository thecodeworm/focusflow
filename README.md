# Ringlet

A calm, precise Pomodoro timer for macOS and Windows. It has a floating
always-on-top widget, focus music built in (YouTube embeds, direct audio links,
and offline noise), simple tasks, and local statistics.

Built with **Tauri 2 + Rust** on the native side and **React 19 + TypeScript +
Tailwind CSS 4** (shadcn/ui-style components on Radix, Motion, Lucide, Zustand)
in the UI. Everything stays on your machine: there are no accounts, no
telemetry, and no backend.

---

## Architecture

```
┌────────────── Rust process (src-tauri) ──────────────────────────────┐
│ TimerService ── single source of truth                               │
│   engine.rs   pure state machine (clock-free, unit-tested)           │
│   clock.rs    two monotonic clocks: "awake" and "awake + asleep"     │
│   ticker thread: sleeps on a Condvar while idle (0 % CPU), wakes     │
│   once per displayed second while running                            │
│ settings.rs   schema + tolerant loading → tauri-plugin-store         │
│ db.rs         SQLite (rusqlite): tasks + completed sessions          │
│ windows.rs    widget / dashboard windows, sizing, monitor checks     │
│ platform/     macOS (AppKit/CoreAnimation) & Windows (DWM) tweaks    │
│ tray.rs       menu bar / notification-area icon + menu               │
│ shortcuts.rs  global shortcuts with per-shortcut conflict reporting  │
│ sound.rs      synthesized completion chimes (rodio), no audio files  │
│ player_server loopback host for the YouTube embed page               │
│ commands.rs   typed IPC surface                                      │
└───────────────▲──────────────────────────────┬───────────────────────┘
       commands │                              │ events (timer://state, …)
┌───────────────┴───────┐              ┌───────▼──────────────────────┐
│ "widget" window       │◀─ music:// ─▶│ "main" dashboard window      │
│ compact/standard/     │   events     │ Timer · Music · Tasks ·      │
│ expanded layouts      │              │ Statistics · Settings        │
└───────────────────────┘              │ plays all media              │
                                       └──────────────────────────────┘
```

* **One timer.** Windows never count time. They send commands (`timer_toggle`, …)
  and render the snapshots Rust broadcasts. Every snapshot carries a sequence
  number, so a stale one that arrives late is ignored. Rust serializes
  commands, which makes rapid start/pause clicks harmless.
* **Low CPU.** Per-second ticks go only to *visible* windows. The progress ring
  animates with a 1-second linear CSS transition per tick, so there is no
  `requestAnimationFrame` loop. A paused or idle timer uses no CPU.
* **Separate bundles.** The widget loads an 11 KB chunk. The dashboard code
  loads only in the dashboard window.

## Timer accuracy

The countdown never relies on `setInterval`. Time is measured with two
monotonic clocks that are unaffected by changes to the system clock:

| | macOS | Windows |
|---|---|---|
| awake time | `CLOCK_UPTIME_RAW` | `QueryUnbiasedInterruptTime` |
| awake + asleep | `CLOCK_MONOTONIC_RAW` | `GetTickCount64` |

At each tick, the difference between the two clocks is the time the machine
spent asleep. The **Count time asleep** setting (Settings → Timer) controls
what happens with it:

* **On (default):** a session started before sleep keeps counting down.
  If it ended while the machine was asleep, it completes on wake. You get one
  notification, and the session is recorded once.
* **Off:** the countdown pauses while the machine is asleep.

**Wall-clock changes** (manual, NTP, time-zone) never affect a running session.

**When the process isn't running** (Quit, crash, or the OS terminating the
app), Ringlet persists the engine state on every change and every 30 s while
running. On the next launch:

| Saved state | Behavior on relaunch |
|---|---|
| idle / paused | restored exactly |
| running, deadline still ahead | keeps running; the time Ringlet was closed counts |
| running, deadline passed | recorded as completed (flagged `recovered`); the next phase is prepared but **not** auto-started; a notice is shown |
| clock now earlier than the save time | restored as **paused** at the last known remaining time |

Sessions you **reset, skip or abandon are never recorded.** Completions are
recorded exactly once. The engine changes state atomically, and the database
has a unique key per session (`INSERT OR IGNORE`).

## Music

### Direct audio
Ringlet plays HTTPS links to files or streams that the system WebView can
decode, such as MP3, AAC/M4A, Ogg/Opus, WAV and FLAC. Codec support depends on
the platform. HLS (`.m3u8`) works on macOS but generally not on Windows.
Plain `http://` links, credentials in the URL, `file:`, `data:` and
`javascript:` links are rejected. Links to streaming web pages (Spotify,
SoundCloud, Apple Music, …) get an explanation instead of a failed attempt.

### YouTube
YouTube plays through the **official IFrame Player API**. Ringlet does not
scrape, extract or download anything.

* YouTube embeds require the embedding page to have an HTTP(S) origin and to
  send a Referer (otherwise you get *Error 153*). Tauri serves the app from
  `tauri://localhost` on macOS, so the Rust side serves **one static page** from
  `http://127.0.0.1:<random port>/player.html`. That page loads the IFrame API
  and receives commands from the dashboard through `postMessage`, checked
  against the exact origin. The server only answers `GET /player.html` and
  `/player.js`, validates the `Host` header, sets a strict CSP and
  `frame-ancestors`, and has no IPC access.
* On the Music page the player is visible at ≥ 480 × 270 (scales with the
  window). On other dashboard pages it docks as a visible 356 × 200 mini player.
  The iframe is never re-parented, hidden, covered or shrunk below YouTube's
  minimum.
* **Pause videos when the dashboard is hidden** is on by default. Closing the
  dashboard pauses YouTube, and reopening it resumes. If you press play in the
  widget while the dashboard is hidden, Ringlet brings the dashboard forward
  first. Direct audio and focus sounds keep playing in the background.
* Errors are reported, never faked: embedding disabled (101/150), removed or
  private (100), invalid ID (2), autoplay blocked (shows a prompt to press play
  on the video), offline, and API unreachable. Titles come only from YouTube's
  player.
* Ads, regional restrictions and age gates are YouTube's. Ringlet doesn't
  promise ad-free or audio-only playback.

### Your Focus Sounds
White, pink and brown noise are generated with the Web Audio API. They work
offline, have their own volume, and can play alongside music.

## Development

### Prerequisites
* **Node.js 20+** (tested with 24) and npm
* **Rust** stable via [rustup](https://rustup.rs) (tested with 1.99)
* **macOS:** Xcode Command Line Tools (`xcode-select --install`)
* **Windows:** Microsoft C++ Build Tools ("Desktop development with C++") and
  WebView2 (preinstalled on Windows 10 21H2+/11)

> **Apple Silicon note:** if your terminal runs under Rosetta (`uname -m` prints
> `x86_64` on an M-series Mac), install the native toolchain with
> `rustup default stable-aarch64-apple-darwin` or prefix commands with
> `arch -arm64`.

### Run

```bash
npm install
npm run app:dev        # tauri dev: Vite + Rust, hot reload for the UI
```

### Checks

```bash
npm test               # Vitest: timer state, URL parsing, stats/day boundaries, shortcuts, ring math
npm run typecheck      # tsc --noEmit (strict)
npm run lint           # ESLint incl. react-hooks rules
cd src-tauri && cargo test   # Rust: engine, recovery, settings, DB, player host, URL policies, sounds
```

### Release builds

**macOS** (run on a Mac):
```bash
npm run app:build                                   # host architecture → .app + .dmg
npm run tauri build -- --target aarch64-apple-darwin
npm run tauri build -- --target x86_64-apple-darwin # rustup target add x86_64-apple-darwin
npm run tauri build -- --target universal-apple-darwin  # needs both targets
```
Output: `src-tauri/target/<target>/release/bundle/{macos,dmg}/`.
Without signing, Gatekeeper requires right-click → Open the first time. For
distribution, set `APPLE_SIGNING_IDENTITY` and the notarization variables
described in the [Tauri docs](https://v2.tauri.app/distribute/sign/macos/).

**Windows** (run on Windows 10/11 x64):
```powershell
npm install
npm run app:build      # → NSIS installer (.exe) and MSI in src-tauri\target\release\bundle\
```
The installer downloads the WebView2 runtime if it is missing. Cross-compiling
the Windows bundle from macOS is not supported by this setup.

### Publishing an update

Installed copies update themselves. Bump nothing by hand — just tag:
```bash
git tag v1.0.1 && git push origin v1.0.1
```
The Release workflow builds both platforms with the tag's version, signs the
update bundles and publishes `latest.json` with the GitHub Release. Ringlet
checks it 20 seconds after launch and every 4 hours, downloads a new version in
the background, and applies it the next time the timer is idle and the
dashboard is closed (or from the tray's **Restart to Update**, or on quit).

Update bundles are signed with a key whose public half is in
`tauri.conf.json`. The private key lives at `~/.tauri/ringlet-updater.key` and
in the `TAURI_SIGNING_PRIVATE_KEY` repository secret — keep a backup; if it is
lost, installed copies can never be updated again. Local `tauri build` needs
the key too:
```bash
export TAURI_SIGNING_PRIVATE_KEY="$(cat ~/.tauri/ringlet-updater.key)"
```

### Regenerating icons
```bash
npm run icons          # rasterizes the icon from code, then runs `tauri icon`
```

## Keyboard shortcuts

Global defaults use three modifiers to avoid conflicts. You can change or
disable them in Settings → Desktop.

| Action | macOS | Windows |
|---|---|---|
| Start / pause | ⌥⇧⌘P | Ctrl+Alt+Shift+P |
| Reset session | ⌥⇧⌘R | Ctrl+Alt+Shift+R |
| Show / hide floating timer | ⌥⇧⌘W | Ctrl+Alt+Shift+W |
| Open dashboard | ⌥⇧⌘D | Ctrl+Alt+Shift+D |
| Toggle always on top | ⌥⇧⌘T | Ctrl+Alt+Shift+T |

If the OS refuses a shortcut (for example because another app owns it), the
reason appears next to that shortcut. In-window keys: **Space** start/pause,
**R** reset, **S** skip.

## Data & privacy

Everything lives in the app data directory
(`~/Library/Application Support/app.ringlet.desktop` on macOS,
`%APPDATA%\app.ringlet.desktop` on Windows):

| File | Contents |
|---|---|
| `settings.json` | preferences, presets, favorites (Tauri Store) |
| `state.json` | timer state for crash/restart recovery |
| `window.json` | widget position |
| `ringlet.db` | tasks and completed sessions (SQLite) |

If a JSON file is corrupt, it is moved aside as `*.corrupt-<timestamp>.json`
and Ringlet starts with defaults and shows a notice. Fields with an invalid
type fall back to their defaults one at a time instead of discarding the whole
file. An unreadable database is set aside the same way.

### Security
* Tauri capabilities grant only `core:event:default` and
  `core:window:allow-start-dragging`. Plugin JavaScript APIs (fs, shell, http,
  store, sql, …) are not exposed. All functionality goes through typed
  commands that validate their input.
* The CSP allows scripts from `'self'` only. Frames are allowed only from the
  loopback player host, media only over `https:`, and images only from self,
  data URIs and YouTube thumbnails.
* Navigation away from the app is blocked. New-window requests from the embed
  (YouTube logo, title) open in your browser, and only for an allow-list of
  YouTube/Google HTTPS hosts.
* A second launch focuses the running instance instead of starting a
  competing timer (single-instance plugin).
* Release builds strip symbols and contain no devtools.

## Platform notes & known limitations

* **Over full-screen apps (macOS):** **Show over full-screen apps** (Settings →
  Desktop) is on by default, and Ringlet keeps its Dock icon. At launch the
  widget is turned into a *non-activating `NSPanel`* (the mechanism
  Spotlight-style overlays use). Its instance is re-classed with
  `object_setClass` to a small `NSPanel` subclass that mirrors what Tauri's
  `TaoWindow` adds. The panel has the `fullScreenAuxiliary` + `canJoinAllSpaces`
  collection behaviors and sits at the status window level (25) while pinned.
  Clicking it never activates Ringlet, so you stay in your full-screen app.
  Before re-classing, Ringlet checks at runtime that `NSPanel` has the same
  instance layout as `NSWindow`. If a future macOS changes that, it skips the
  conversion and falls back to running as a menu-bar (accessory) app, with no
  Dock icon and the menu bar icon always shown. All APIs used are public
  Objective-C runtime and AppKit API.
  Still not covered: the lock screen, the login window, screen-saver, and
  other protected system surfaces. On Windows, exclusive-fullscreen games
  bypass the desktop compositor and can't be overlaid. Borderless-fullscreen
  apps are fine.
* **Rounded widget corners:** on macOS they come from a Core Animation layer
  mask on the window (public AppKit APIs; no `macOSPrivateApi`, no transparent
  WebView). On Windows 11, DWM rounds corners at 8 px. Windows 10 shows square
  corners.
* **Widget opacity:** `NSWindow.alphaValue` on macOS. On Windows it uses a
  layered window (`WS_EX_LAYERED`). WebView2 compositing inside layered windows
  varies by driver, so if the widget renders incorrectly at < 100 %, set the
  opacity back to 100 %.
* **Notifications in dev builds:** macOS attributes notifications from
  `tauri dev` to the terminal app, and they may not appear. Use a bundled build
  to test them. Ringlet can't read macOS's real per-app notification
  permission, so if nothing appears, check System Settings → Notifications.
* **Media autoplay:** WebKit and WebView2 may block autoplay. Ringlet detects
  this and asks you to press play instead of claiming playback started.
* **YouTube** behavior (ads, embedding restrictions, playlists that refuse
  embedding, region locks) is outside Ringlet's control.
* **Sleep handling** applies while Ringlet is running. If the OS terminates
  the app *and* the machine sleeps, relaunch recovery uses wall-clock time (see
  the table above).
* Statistics bucket days in your **current** time zone. After you travel,
  past sessions are re-bucketed into the new zone's days.

* **DMG in restricted terminals:** `tauri build` styles the DMG window through
  Finder AppleScript. If the terminal lacks Automation permission, the DMG step
  fails (the `.app` is still built). Run
  `bash src-tauri/target/release/bundle/dmg/bundle_dmg.sh --skip-jenkins --volname Ringlet Ringlet.dmg src-tauri/target/release/bundle/macos/Ringlet.app`
  to build an unstyled DMG instead.

### What has been verified (macOS 26, Apple Silicon)
* 31 Rust tests and 48 Vitest tests pass. Strict `tsc` and ESLint report no errors.
* `tauri dev` and the release `.app` launch. They create settings, the database and
  the widget position file, and idle at ~0.1 % CPU.
* The release `.app` (5.6 MB, arm64) and DMG (2.9 MB, `hdiutil verify`) build.
* The loopback player host rejects foreign `Host` headers, non-GET requests and
  unknown paths, and release builds allow only `tauri://` parent origins.
* The official YouTube embed loads through the loopback host (handshake → API
  ready → player ready). YouTube returned a real embedding error (150) for an
  embed-disabled video, not Error 153.
* Every dashboard page and all three widget sizes were rendered in light and
  dark mode in headless Chrome with mocked IPC, with no console errors.

**Not verified here:** Windows (not compiled or run). On macOS, I didn't
interact with the native windows by hand (dragging, tray clicks, notifications,
sleep/wake) because the environment had no screen-recording or accessibility
access. That logic is covered by unit tests.
